# `Store`
Essential
A `Store` is the main location for keeping both tabular data and keyed values.
Create a `Store` easily with the [`createStore`](https://tinybase.org/api/the-essentials/creating-stores/createstore/) function. From there, you can set and get data, add listeners for when the data changes, set schemas, and so on.
A `Store` has two facets. It can contain keyed [`Values`](https://tinybase.org/api/store/type-aliases/store/values/), and independently, it can contain tabular [`Tables`](https://tinybase.org/api/store/type-aliases/store/tables/) data. These two facets have similar APIs but can be used entirely independently: you can use only tables, only keyed [`Values`](https://tinybase.org/api/store/type-aliases/store/values/), or both tables _and_ keyed [`Values`](https://tinybase.org/api/store/type-aliases/store/values/) - all in a single `Store`.
## Keyed values
The keyed value support is best thought of as a flat JavaScript object. The `Store` contains a number of [`Value`](https://tinybase.org/api/store/type-aliases/store/value/) objects, each with a unique ID, and which is a string, boolean, number, null (since v7.0), or a plain JavaScript object or array (since v8.0).

```
{                           // Store
  "value1": "one",            // Value (string)
  "value2": true,             // Value (boolean)
  "value3": 3,                // Value (number)
  "value4": null,             // Value (null since v7.0)
  "value5": {"x": 1},         // Value (object since v8.0)
  "value6": [1, 2, 3],        // Value (array since v8.0)
  ...
}

```

In its default form, a `Store` has no sense of a structured schema for the [`Values`](https://tinybase.org/api/store/type-aliases/store/values/). However, you _can_ optionally specify a [`ValuesSchema`](https://tinybase.org/api/store/type-aliases/schema/valuesschema/) for a `Store`, which then usefully constrains and defaults the [`Values`](https://tinybase.org/api/store/type-aliases/store/values/) you can use.
## Tabular data
The tabular data exists in a simple hierarchical structure:
  * The `Store` contains a number of [`Table`](https://tinybase.org/api/store/type-aliases/store/table/) objects.
  * Each [`Table`](https://tinybase.org/api/store/type-aliases/store/table/) contains a number of [`Row`](https://tinybase.org/api/store/type-aliases/store/row/) objects.
  * Each [`Row`](https://tinybase.org/api/store/type-aliases/store/row/) contains a number of [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) objects.


A [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) is a string, boolean, number, null (since v7.0), or a plain JavaScript object or array (since v8.0).
The members of each level of this hierarchy are identified with a unique [`Id`](https://tinybase.org/api/common/type-aliases/identity/id/) (which is a string). In other words you can naively think of a `Store` as a three-level-deep JavaScript object, keyed with strings:

```
{                     // Store
  "table1": {           // Table
    "row1": {             // Row
      "cell1": "one",       // Cell (string)
      "cell2": true,        // Cell (boolean)
      "cell3": 3,           // Cell (number)
      "cell4": null,        // Cell (null since v7.0)
      "cell5": {"x": 1},    // Cell (object since v8.0)
      "cell6": [1, 2, 3],   // Cell (array since v8.0)
      ...
    },
    ...
  },
  ...
}

```

Again, by default `Store` has no sense of a structured schema. As long as they are unique within their own parent, the [`Id`](https://tinybase.org/api/common/type-aliases/identity/id/) keys can each be any string you want. However, as you _can_ optionally specify a [`TablesSchema`](https://tinybase.org/api/store/type-aliases/schema/tablesschema/) for the tabular data in a `Store`, which then usefully constrains the [`Table`](https://tinybase.org/api/store/type-aliases/store/table/) and [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) [`Ids`](https://tinybase.org/api/common/type-aliases/identity/ids/) (and [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) values) you can use.
## Setting and getting data
Every part of the `Store` can be accessed with getter methods. When you retrieve data from the `Store`, you are receiving a copy - rather than a reference - of it. This means that manipulating the data in the `Store` must be performed with the equivalent setter and deleter methods.
To benefit from the reactive behavior of the `Store`, you can also subscribe to changes on any part of it with 'listeners'. Registering a listener returns a listener [`Id`](https://tinybase.org/api/common/type-aliases/identity/id/) (that you can use later to remove it with the [`delListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/dellistener/) method), and it will then be called every time there is a change within the part of the hierarchy you're listening to.
This table shows the main ways you can set, get, and listen to, different types of data in a `Store`:

|  [`Value`](https://tinybase.org/api/store/type-aliases/store/value/) [`Ids`](https://tinybase.org/api/common/type-aliases/identity/ids/)  | [`getValueIds`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/getvalueids/)  | -  | -  | [`addValueIdsListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addvalueidslistener/)  |

| [`Row`](https://tinybase.org/api/store/type-aliases/store/row/)  | [`getRow`](https://tinybase.org/api/the-essentials/getting-data/getrow/)  | [`setRow`](https://tinybase.org/api/the-essentials/setting-data/setrow/)  | [`delRow`](https://tinybase.org/api/store/interfaces/store/store/methods/deleter/delrow/)  | [`addRowListener`](https://tinybase.org/api/the-essentials/listening-for-changes/addrowlistener/)  |  
|  [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) [`Ids`](https://tinybase.org/api/common/type-aliases/identity/ids/)  | [`getCellIds`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/getcellids/)  | -  | -  | [`addCellIdsListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addcellidslistener/)  |  
| [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/)  | [`getCell`](https://tinybase.org/api/the-essentials/getting-data/getcell/)  | [`setCell`](https://tinybase.org/api/the-essentials/setting-data/setcell/)  | [`delCell`](https://tinybase.org/api/store/interfaces/store/store/methods/deleter/delcell/)  | [`addCellListener`](https://tinybase.org/api/the-essentials/listening-for-changes/addcelllistener/)  |  
There are two extra methods to manipulate [`Row`](https://tinybase.org/api/store/type-aliases/store/row/) objects. The [`addRow`](https://tinybase.org/api/the-essentials/setting-data/addrow/) method is like the [`setRow`](https://tinybase.org/api/the-essentials/setting-data/setrow/) method but automatically assigns it a new unique [`Id`](https://tinybase.org/api/common/type-aliases/identity/id/). And the [`setPartialRow`](https://tinybase.org/api/store/interfaces/store/store/methods/setter/setpartialrow/) method lets you update multiple [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) values in a [`Row`](https://tinybase.org/api/store/type-aliases/store/row/) without affecting the others. There is a similar [`setPartialValues`](https://tinybase.org/api/store/interfaces/store/store/methods/setter/setpartialvalues/) method to do the same for the [`Values`](https://tinybase.org/api/store/type-aliases/store/values/) in a `Store`.
You can listen to attempts to write invalid data to a [`Value`](https://tinybase.org/api/store/type-aliases/store/value/) or [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) with the [`addInvalidValueListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addinvalidvaluelistener/) method or [`addInvalidCellListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addinvalidcelllistener/) method.
The [`transaction`](https://tinybase.org/api/the-essentials/setting-data/transaction/) method is used to wrap multiple changes to the `Store` so that the relevant listeners only fire once.
The [`setJson`](https://tinybase.org/api/store/interfaces/store/store/methods/setter/setjson/) method and the [`getJson`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/getjson/) method allow you to work with a JSON-encoded representation of the entire `Store`, which is useful for persisting it.
Finally, the [`callListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/calllistener/) method provides a way for you to manually provoke a listener to be called, even if the underlying data hasn't changed. This is useful when you are using mutator listeners to guarantee that data conforms to programmatic conditions, and those conditions change such that you need to update the `Store` in bulk.
Read more about setting and changing data in [The Basics](https://tinybase.org/guides/the-basics/) guides, and about listeners in the Listening to Stores guide.
## Creating a schema
You can set a [`ValuesSchema`](https://tinybase.org/api/store/type-aliases/schema/valuesschema/) and a [`TablesSchema`](https://tinybase.org/api/store/type-aliases/schema/tablesschema/) with the [`setValuesSchema`](https://tinybase.org/api/store/interfaces/store/store/methods/setter/setvaluesschema/) method and [`setTablesSchema`](https://tinybase.org/api/store/interfaces/store/store/methods/setter/settablesschema/) method respectively. A [`TablesSchema`](https://tinybase.org/api/store/type-aliases/schema/tablesschema/) constrains the [`Table`](https://tinybase.org/api/store/type-aliases/store/table/) [`Ids`](https://tinybase.org/api/common/type-aliases/identity/ids/) the `Store` can have, and the types of [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) data in each [`Table`](https://tinybase.org/api/store/type-aliases/store/table/). Each [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/) requires its type to be specified, and can also take a default value for when it's not specified.
You can also get a serialization of the schemas out of the `Store` with the [`getSchemaJson`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/getschemajson/) method, and remove the schemas altogether with the [`delValuesSchema`](https://tinybase.org/api/store/interfaces/store/store/methods/deleter/delvaluesschema/) method and [`delTablesSchema`](https://tinybase.org/api/store/interfaces/store/store/methods/deleter/deltablesschema/) method.
Read more about schemas in the [Using Schemas](https://tinybase.org/guides/schemas/using-schemas/) guide.
## Convenience methods
There are a few additional helper methods to make it easier to work with a `Store`. There are methods for easily checking the existence of a [`Table`](https://tinybase.org/api/store/type-aliases/store/table/), [`Row`](https://tinybase.org/api/store/type-aliases/store/row/), or [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/), and iterators that let you act on the children of a common parent:  
|   | Checking existence  | Iterator  |  
| --- | --- | --- |  
| [`Value`](https://tinybase.org/api/store/type-aliases/store/value/)  | [`hasValue`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/hasvalue/)  | [`forEachValue`](https://tinybase.org/api/store/interfaces/store/store/methods/iterator/foreachvalue/)  |  
| [`Table`](https://tinybase.org/api/store/type-aliases/store/table/)  | [`hasTable`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/hastable/)  | [`forEachTable`](https://tinybase.org/api/store/interfaces/store/store/methods/iterator/foreachtable/)  |  
| [`Row`](https://tinybase.org/api/store/type-aliases/store/row/)  | [`hasRow`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/hasrow/)  | [`forEachRow`](https://tinybase.org/api/store/interfaces/store/store/methods/iterator/foreachrow/)  |  
| [`Cell`](https://tinybase.org/api/store/type-aliases/store/cell/)  | [`hasCell`](https://tinybase.org/api/store/interfaces/store/store/methods/getter/hascell/)  | [`forEachCell`](https://tinybase.org/api/store/interfaces/store/store/methods/iterator/foreachcell/)  |  
Since v4.3.23, you can add listeners for the change of existence of part of a `Store`. For example, the [`addHasValueListener`](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addhasvaluelistener/) method lets you listen for a [`Value`](https://tinybase.org/api/store/type-aliases/store/value/) being added or removed.
Finally, the [`getListenerStats`](https://tinybase.org/api/store/interfaces/store/store/methods/development/getlistenerstats/) method describes the current state of the `Store`'s listeners for debugging purposes.
## Example
This example shows a very simple lifecycle of a `Store`: from creation, to adding and getting some data, and then registering and removing a listener.

```
import {createStore} from 'tinybase';

const store = createStore[](https://tinybase.org/api/the-essentials/creating-stores/createstore/)().setTables[](https://tinybase.org/api/store/interfaces/store/store/methods/setter/settables/)({pets: {fido: {species: 'dog'}}});
console.log(store.getRow[](https://tinybase.org/api/the-essentials/getting-data/getrow/)('pets', 'fido'));
// -> {species: 'dog'}

store.setCell[](https://tinybase.org/api/the-essentials/setting-data/setcell/)('pets', 'fido', 'color', 'brown');
console.log(store.getCell[](https://tinybase.org/api/the-essentials/getting-data/getcell/)('pets', 'fido', 'color'));
// -> 'brown'

const listenerId = store.addTableListener[](https://tinybase.org/api/store/interfaces/store/store/methods/listener/addtablelistener/)('pets', () => {
  console.log('changed');
});

store.setCell[](https://tinybase.org/api/the-essentials/setting-data/setcell/)('pets', 'fido', 'sold', false);
// -> 'changed'

store.delListener[](https://tinybase.org/api/store/interfaces/store/store/methods/listener/dellistener/)(listenerId);

```
