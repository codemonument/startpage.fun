# Implementation Details

Working list of currently decided implementation details for `startpage.fun`.

## Reference assets

- UI reference image: `meta/reference/speeddial-2-reference.png`

## Product target

- Ship as a web-first, offline-capable PWA at `startpage.fun`
- v1 ships with one strong default visual theme only
- v1 uses one global visual system rather than per-Space visual customization
- Users can set a custom page background image in v1
- Background image input modes match Dial custom images:
  - upload a local image file
  - paste an external image URL, then download and store it locally
  - paste actual image data, then store it locally
- Background image is global for the whole app, not per-Space
- Background images are normalized/processed on ingest for performance and consistency
- Background image fit/position is automatic in v1; there is no user adjustment yet, partly because one manual setting would likely fail across both mobile and desktop layouts
- Users can easily remove a custom background image and return to the default background
- Do not build a browser extension for v1
- Treat this as a browser startup/home page, not a true new-tab replacement

## Frontend stack

- Use **Solid 1.x stable** for v1
- Use **Tailwind CSS** as the primary styling system
- Use **Vite** with **vite-plugin-solid** and **vite-plugin-pwa** for the app shell/build baseline
- Use **Kobalte** for headless UI primitives
- Use **fuzzysort** for Dial Search and Command Box matching
- Use **Valibot** for schema validation of persisted data, drafts, settings, and form inputs

## Data and storage

- v1 is local-first
- Source of truth is local browser storage on the current device
- No account system in v1
- Cloud sync may be added later
- Use **Dexie** for IndexedDB-backed structured local data
- Store Dial icon assets in IndexedDB
- Store the background image in OPFS, keeping both original and compressed variants

## Testing strategy

- Keep the initial test setup as simple as possible
- Use **Vitest** for pure logic/domain tests
- Prefer as little mocking as possible
- Use **Playwright** for complete browser end-to-end tests
- Skip the middle mocked/component-testing layer for now unless it proves clearly worthwhile later
- Defer **@testing-library/*** until a real need appears
- Defer **fake-indexeddb** until real Dexie repository tests justify it
- Major vertical slices should each add at least one happy-path browser E2E test
- Prefer setting up E2E test state through real UI flows rather than test-only seed helpers
- Do not add visual/screenshot assertion testing in the initial setup

## Core UI model

- The top-level grouping unit is a **Space**
- Every Space has a required user-visible name
- Space names must be unique within a Library
- Users can create, rename, reorder, and delete Spaces in v1
- A Library must always contain at least one Space
- The last remaining Space cannot be deleted
- By default, the app reopens the last active Space on load
- Global settings should allow switching between reopening the last active Space and opening a user-chosen default Space
- Deleting a non-empty Space should ask whether to delete its Dials or move them to another Space first
- If the deleted Space is the configured default Space, communicate that the app will fall back to reopening the last active Space and allow the user to select another default Space instead
- Destructive deletion of a non-empty Space should require typing the Space name as confirmation
- The grid contains **Tiles**
- In v1, Tile types are **Dial** and **Add Tile**
- By default, each Space includes an Add Tile at the end
- The Add Tile is fixed at the end and is not draggable
- Dial Order applies only to Dials; the Add Tile is appended by render rule and not part of persisted ordering
- Global settings should allow showing the Add Tile only on empty Spaces instead
- If the Add Tile is hidden in non-empty Spaces, users should still be able to create Dials through a Space-level add button and the Command Box
- The Add Tile is system-generated by invariant, not managed like normal user content
- No folders in v1
- Tabs in the UI are a switching control for Spaces
- On touch devices, tapping a Space tab switches Spaces immediately
- Space tabs should support a secondary-action menu for Space operations
- On touch devices, long press on a Space tab opens the Space menu
- Global settings should allow three Space bar overflow modes:
  - horizontally scrollable
  - overflow menu
  - multi-row overflow
- Default Space bar overflow mode is multi-row overflow
- "Overflow menu" mode is effectively multi-row overflow with a row cap of 1
- Multi-row overflow mode uses capped rows rather than unlimited wrapping
- When the row cap is exceeded in multi-row mode, extra Spaces move into an overflow menu
- The row cap for multi-row overflow mode is configurable
- Spaces inside the overflow menu remain full-featured, including switching, focus, and Space menu actions
- Space drag-reordering works across the overflow boundary, including moving visible Spaces into overflow and overflowed Spaces back into visible rows
- When dragging an overflowed Space, start from the overflow menu entry and keep a drag proxy alive outside the menu
- Spaces also support keyboard reordering in v1
- Space menu actions in v1:
  - Rename Space
  - Delete Space
  - Set as default Space
  - Create new Space after this one
- "Create new Space after this one" creates a named empty Space with no Dials and an Add Tile
- Space creation prompts for a required Space name immediately

## Dial creation and editing

- Dialog forms auto-save draft state while open, but store it separately from committed Dial/Space/Settings data
- Maintain a dedicated draft-storage area for these in-progress dialog values
- Reopening a dialog starts from committed state by default, but offers a "Restore draft" action when a saved draft exists
- A successful explicit save deletes the corresponding draft
- Explicitly discarding a dialog also discards its saved draft
- Cancelling a dialog by clicking outside it keeps the saved draft
- New Dials are created manually
- Manual add requires a URL; title is optional
- Default Dial title is the URL hostname including subdomains
- Dial titles do not need to be unique within a Space
- Duplicate Dial URLs are allowed even within the same Space
- The Dial Editor should warn when another active Dial already has the same URL, regardless of title, and should show/link to where that existing Dial lives
- This duplicate warning is informational only and does not block saving
- Dial Editor currently includes:
  - URL
  - title
  - icon
  - space assignment
- Dial icon choices in the editor:
  - favicon
  - generated text fallback
  - custom icon
- Custom icon input modes:
  - upload a local image file
  - paste an external image URL, then download and store it locally like an uploaded file
  - paste actual image data, then store it locally like an uploaded file
- Custom icons are normalized on ingest into a standard icon form for display consistency
- If favicon is selected, the editor should expose a manual refresh action
- If a user has previously uploaded or otherwise stored a custom icon, switching away from it to favicon must not discard the stored custom file
- If the user later switches back to the custom icon choice, the previously stored custom file should still be available unless the user explicitly replaces it

## Icon behavior

- v1 is icon-first only
- Preferred icon source order:
  1. favicon
  2. generated text-on-white fallback
  3. searched internet icon later
  4. LLM-generated icon later
- Try to resolve favicon on save
- If favicon is not resolvable, store a text-only fallback immediately for fast render
- Retry favicon loading in the background on later loads only for Dials still using a text-only fallback

## Launch behavior

- Default launch opens in the current tab
- There is a global setting to reverse that default so launch opens in a new tab
- Middle click always opens in a new tab

## Global chrome

- The app has a small toolbar in the top-right corner
- The Trash view lives there as a trash-can icon control
- When Trash is opened, keyboard focus moves to the trash-can control first
- Trash has no dedicated back/close button; exiting Trash happens by selecting another Space tab
- Invoking "open Trash" while Trash is already open is a no-op
- Opening Trash always starts from the top rather than restoring previous Trash scroll/focus state

## Dial actions

- Left click performs launch
- On touch devices, tap also launches immediately
- Right click / `contextmenu` opens a custom Dial menu
- On touch devices, long press opens the Dial menu
- For touch interaction, try: long press opens the Dial menu, while drag starts via direct drag gesture
- If that proves unreliable in practice, evaluate split long-press timing: shorter long press for drag, longer long press for menu
- Dial menu currently includes:
  - Open in new tab
  - Edit
- Edit opens a dialog-based Dial Editor
- Do not rely on handing control back to the native browser context menu from the custom menu

## Layout and interaction

- Grid density responds automatically to viewport size by default
- Grid density has no user override in v1
- Dials are manually ordered within a Space
- Dials are drag-and-droppable within a Space
- Touch devices support drag-and-drop reordering in v1
- Cross-Space drag-and-drop is not supported in v1; moving between Spaces happens through the Dial Editor
- When a Dial is moved to another Space via the Dial Editor, it is inserted at the end of that Space content, before the Add Tile
- Dragging Dials to the Trash Space is not supported in v1; deletion happens through other actions
- Use Atlassian **Pragmatic Drag and Drop** for v1 drag/drop

## Search and command surface

- v1 includes search over active saved Dials only
- Trashed Dials do not appear in Dial search results, even when Trash is currently open
- Add Tile does not appear in Dial search results; creating a Dial is exposed as a searchable command instead
- No web search or omnibox-style behavior in v1
- Use a unified `Ctrl+P` / `Cmd+P` command box
- The Command Box also exists on mobile/touch devices, but is primarily relevant when a hardware keyboard is attached (e.g. iPad with keyboard)
- A dedicated mobile button for opening the Command Box may be added later
- Default mode is Dial search across the whole Library, similar to VS Code file search
- Search lists matching Dials individually even when multiple active Dials share the same URL
- Search results always show the Space name for each Dial
- Search results show title, Space name, and the hostname including subdomains
- Dial Search matches against the Dial title, the hostname including subdomains, and the full URL
- Search ranking should prefer title matches first, then hostname matches, then deeper URL/path matches
- `Ctrl+Shift+P` / `Cmd+Shift+P` or a leading `>` switches the same box into command mode
- Reopening the Command Box always starts in default Dial Search mode
- In Dial search mode:
  - default behavior: Enter launches the selected Dial
  - arrow/focus can preview result context without automatically switching Spaces
  - global settings should allow an alternate mode where Enter focuses the Dial and arrow/focus opens it
  - in that alternate mode, "opens" means switching to the Dial's Space and focusing that Dial without launching it
- Initial command examples:
  - create a new Dial
  - start editing the focused Dial
  - create a new Space
  - edit the focused Space
  - delete the focused Space
  - open Trash
  - restore most recently deleted Dial from current Space
  - restore focused trashed Dial
  - permanently delete focused trashed Dial
  - purge Trash
  - open settings
  - settings-related toggle/navigation commands
  - direct settings actions
- Trash is not part of default Dial Search results; it is opened via the dedicated global control or the "open Trash" command
- Direct settings actions from Command Mode apply immediately
- Immediate settings actions show lightweight confirmation feedback in the Command Box
- After a direct settings action runs, the Command Box closes automatically
- Successful command execution generally closes the Command Box
- Commands that open other UI surfaces follow the same focus-destination rules as the equivalent direct actions
- Failed commands keep the Command Box open and show why they failed
- Disabled commands already show their explanation inline, so pressing Enter on them does nothing
- Disabled commands remain keyboard-selectable in the Command Box so their inline explanation can be read predictably
- In Command Mode, destructive actions still use their normal confirmation flow by default
- Invoking a destructive command with `Shift+Enter` implicitly accepts the confirmation step
- Command Box UI should show keyboard hints for alternate invocation behaviors such as `Shift+Enter`
- The "create new Dial" command targets the currently active Space
- Newly created Dials are inserted at the end of the current Space content, just before the Add Tile
- Activating the Add Tile or the "create new Dial" command opens the Dial Editor immediately
- In Dial creation, URL is the only required field
- Changing a Dial URL should re-resolve dependent defaults while preserving explicit user overrides
- Deleting a Dial does not require confirmation; it moves the Dial into a Trash Space instead of deleting it permanently
- The Trash Space is special and should be accessed separately rather than appearing like a normal Space in the Space bar
- The Trash Space is system-defined and cannot be renamed, reordered, or deleted
- Provide a dedicated global control/button to access the Trash Space in v1
- Opening Trash replaces the main Space view with the Trash view
- While Trash is open, the normal Space tabs remain visible
- While Trash is open, normal Space tabs do not show an active highlighted Space
- While Trash is open, the trash-can icon shows the active state
- Selecting a normal Space while Trash is open closes Trash and switches to that Space
- Users cannot create Dials inside the Trash Space
- The Trash Space does not contain an Add Tile
- Trashed Dials remain launchable so users can verify whether they still work before restoring or purging them
- In Trash, the primary action on a Dial remains Launch
- Trashed Dial context menu actions in v1:
  - Restore
  - Open in new tab
  - Permanently delete
- Per-Dial permanent delete in Trash does not require confirmation
- Per-Dial permanent delete in Trash does not support undo
- Trash UI shows each Dial's original Space name
- Trash UI shows each Dial's deletion time
- Trash keeps Dials indefinitely by default
- Global settings should allow configuring a trash retention time
- Trash UI should show retention/expiry information when retention-based deletion is enabled
- Users should be able to purge Trash contents manually
- Purging Trash requires confirmation
- In v1, purge still means emptying all Trash contents in bulk
- Trashed Dials also support per-Dial permanent delete from their context menu
- Trashed Dials can be restored to their original Space identity if it still exists
- If the original Space was renamed, restore still targets that same Space rather than recreating an old-name Space
- Restored Dials should return to their original Dial Order position if possible
- If exact restoration is not possible, restore as close as possible to the original relative position
- `Ctrl+Z` / `Cmd+Z` in a Space restores the most recently deleted Dial from that Space for up to 60 minutes
- Repeated `Ctrl+Z` / `Cmd+Z` should restore multiple deleted Dials from that Space in reverse deletion order while eligible items remain
- If no eligible recently deleted Dials remain for the current Space, show a lightweight message instead of restoring anything
- Context-sensitive commands should generally still be shown when invalid, but disabled with an explanation of why they are currently unavailable
- Menus should follow the same pattern where appropriate: show unavailable actions disabled with an explanation rather than hiding them
- Disabled menu items remain selectable/focusable so their inline explanation can be read predictably
- In menus, the inline disabled reason appears directly below the disabled item
- Explanations for disabled actions should use short inline reason text rather than tooltips or separate detail panels
- Avoid tooltip-only explanations because they do not work well on mobile
- The command to restore the most recently deleted Dial from the current Space should still be shown when invalid, but disabled with an explanation of why it is currently unavailable
- The purge Trash command should still be shown when Trash is empty, but disabled with an explanation of why it is currently unavailable
- Spaces and Dials should both be keyboard-focusable in v1
- Dials should support arrow-key spatial navigation within the visible grid
- Dials also support keyboard reordering in v1
- Tab / Shift+Tab should move focus between UI regions; arrow keys should navigate within the current focused region
- With a focused Dial, `Shift` + arrow keys move the Dial using true spatial movement based on the visible grid geometry
- Dials do not have additional jump-to-start/end keyboard move shortcuts in v1
- With a focused Space tab, `Shift` + arrow keys move the Space using logical Space order rather than visual row layout
- For Space keyboard reordering: `Shift+Left` moves earlier, `Shift+Right` moves later, `Shift+Up` moves to the start, and `Shift+Down` moves to the end
- After keyboard-moving a Dial or Space, focus remains on the moved item
- If keyboard movement cannot continue in the requested direction, do a no-op with lightweight feedback rather than wrapping
- Keyboard move operations should provide screen-reader-accessible announcements, without requiring a visible status message
- These Shift+arrow move shortcuts must not interfere with text input or editing dialogs
- When Space tabs are focused, arrowing between them should immediately switch the active Space
- After switching Spaces via the Space tabs, focus should remain on the focused Space tab
- Moving focus from the Space bar into the Dial grid should target the first Dial in visual order, or the Add Tile if the Space has no Dials
- The Add Tile participates in keyboard focus order whenever it is visible
- Enter should launch the focused Dial
- The Dial Menu should support keyboard opening via `Shift+F10` / `fn+Shift+F10`
- Also support a configurable custom shortcut for opening the focused Dial's secondary context/menu
- Default custom shortcut is `Space`, but only when a Dial is focused
- The `Space` shortcut must not interfere with text input or editing dialogs

## First-run experience

- Show a starter template chooser on first run
- Initial templates:
  - **Empty**: one empty Space, no tiles
  - **Example**: one Space with real saved example Dials
- Background image choice is independent of Starter Templates
